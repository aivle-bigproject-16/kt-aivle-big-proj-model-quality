# 골든 fixture — 촬영 품질 분류기 (CT)

`ai-infer` 가 학습 노트북과 **같은 입력에 같은 출력**을 내는지 자동 검증하는 표본입니다.

대상 가중치: `quality_ct.pt`
SHA-256 `206000f320381615a2cf4d04e7c4ce535fa920a2da26a931f33e8afe306f26c8`
(v1.8 + v2.0 합침 학습본. 이전 v2.0 단독본과 값이 다르므로 **가중치를 먼저 확인**하십시오.)

## 구성
- 이미지 24장 (FAIL 12 / PASS 12), 전부 학습에 쓰지 않은 셀에서 뽑았습니다
- FAIL 은 5개 실패 케이스를 모두 덮고, 각 케이스에서 **가장 점수가 낮은(어려운) 것**을 골랐습니다
- `ct_beam_hardening_metal_streak` 은 강도 차가 커서 데이터셋별로 2장씩 넣었습니다
- PASS 8장은 **판정선 근처**의 것이라 전처리 오류에 민감합니다

## 파일명 접두어 — 반드시 읽으십시오
두 학습 데이터셋(`v1.8`, `v2.0`)은 파일 이름을 **19,985개 공유**합니다. 이름이 같고 그림이 다릅니다.
그래서 fixture 파일명 앞에 출처를 붙였습니다.

| 접두어 | 출처 | 증강 강도 |
|---|---|---|
| `v18__` | `quality_fail_40k_v1.8_20260730_CT` | 사양 강도 (심함) |
| `v20__` | `quality_fail_v2_output_20260802_CT` | 경계 강도 (약함) |

이미지를 stem 만으로 식별하는 코드를 쓰면 두 그림이 섞입니다.

## 검증 방법
1. `images/` 의 각 파일을 추론 파이프라인에 그대로 넣습니다 (**ROI 자르기·리사이즈 추가 금지**)
2. 나온 logit 을 `expected.json` 의 `expected.logit` 과 비교합니다
3. **|Δ| <= 1e-3 이면 통과.** 벗어나면 전처리가 다릅니다

`label` 은 threshold `-0.622716` 기준입니다. 이 값은 val 에서 고른 것이라
**배포 데이터에서는 재보정해야 합니다**(model_card `output.threshold_rationale` 참조).
threshold 를 바꾸면 label 도 달라지므로 **logit 값으로 검증**하십시오.

## 알고 계셔야 할 두 가지

**`ground_truth`=fail 인데 `label`=PASS 인 것이 2건 있습니다.**
`v20__..._y_2000009160` 과 `v20__..._y_2000011241` 로, 둘 다 v2.0 의 약한 금속 streak 입니다.
모델이 **실제로 놓치는** 표본을 일부러 넣은 것이며 fixture 결함이 아닙니다.
이 검증은 "모델이 맞히는가"가 아니라 "전처리가 같은가"를 봅니다. logit 이 일치하면 통과입니다.

**PASS 12장은 모두 `v18__` 접두어입니다.**
두 데이터셋의 PASS 는 92% 가 바이트 단위로 같은 파일이라 중복을 제거했고, v1.8 쪽 사본이 남았습니다.
v2.0 의 PASS 가 빠진 것이 아니라 같은 파일입니다.
