## 2. severity 층화 평가 (§조사 ②)

증강 이력 JSON에 기록된 물리 파라미터로 FAIL 644장(held-out)을 강도 사분위로 나눴다.
`severity` 필드는 케이스마다 의미가 일정하지 않아 보조로만 썼다.

평가 대상: fold1+fold0 (학습 미사용) 6,231장 — PASS 5,587 / FAIL 644
운영점: clean FPR 3% → threshold 3.5486 (logit) · 전체 fail recall 0.9938

### 2.1 강도 구간별 recall과 여유

| 케이스 | 강도 지표 (약→강) | recall | **여유 중앙값 (약→강)** |
|---|---|---|---|
| `ct_low_signal_noise` | photon 39.9 → 10.3 | 1.000 전 구간 | **10.53 → 10.50** |
| `ct_insufficient_projection_sampling` | retained 0.675 → 0.221 | 1.000 전 구간 | **11.52 → 11.65** |
| `ct_acquisition_motion` | ghost 18.1 → 28.0px | 0.971~1.000 | 9.00 → 9.85 |
| `ct_cell_alignment_failure` | retained 0.82 → 0.60 | 0.967~1.000 | 7.84 → 9.50 |
| `ct_beam_hardening_metal_streak` | streak 24 → 71개 | 0.968~1.000 | 6.73 → 9.19 |

"여유" = `logit − threshold`. recall만으로는 "겨우 넘겼다"와 "압도적으로 넘겼다"를 구별할 수 없어 함께 측정했다.

### 2.2 점수 분포

```
PASS   p1=-12.02   p25=-8.22   p50=-6.39   p75=-3.80   p99=+5.89
FAIL   p1= +4.33   p25=+11.55  p50=+13.37  p75=+14.86  p99=+17.64
운영점 threshold = +3.55
```

두 무리가 약 15 logit 떨어져 있다. FAIL 하위 25%조차 +11.55다.
**데이터에 경계 사례가 사실상 존재하지 않는다.**

### 2.3 당시 해석과 그 한계

광자 수 4배 차이(39.9 → 10.3, SNR 2배)에도 여유가 10.53 → 10.50으로 미동도 없었다.
이를 근거로 "모델이 물리적 강도가 아닌 무언가를 본다 = 파이프라인 흔적" 쪽으로 기울었다.

동시에 반론도 기록해 두었다 — *"사양의 가장 약한 설정조차 이미 결정경계에서 멀리
떨어져 있을 가능성"*. **③에서 이 반론이 맞은 것으로 확인됐다.**

## 3. 강도 스윕 프로브 (§조사 ③) — 결정적 실험

held-out PASS 300장에 **사양 하한보다 훨씬 약한 강도**로 증강을 걸어 점수를 측정했다.

```
원본 그대로                        평균 logit  -5.96    FAIL 판정  3.3%
```

### 3.1 조건 A — 파이프라인 흔적만 (픽셀 변화 0)

| 조건 | 평균 logit | FAIL 판정률 | 원본 대비 |
|---|---|---|---|
| **JPEG 재인코딩만 (픽셀 동일)** | −5.94 | **3.3%** | **+0.02** |
| **noise photon = 1,000,000** (사실상 무변화) | −5.45 | **4.0%** | +0.52 |

→ **물리적 결함이 0이면 모델은 PASS라고 한다. 지문 가설 기각.**
→ JPEG 세대가 하나 더 쌓이는 confound도 없다(+0.02).

### 3.2 조건 B — 저신호 노이즈 스윕 (사양 photon 10~40)

| photon_scale | 평균 logit | FAIL 판정률 |
|---|---|---|
| 1,000,000 | −5.45 | 4.0% |
| 10,000 | −0.59 | 19.7% |
| **≈ 3,000 (내삽)** | **≈ +3.5** | **≈ 50%** ← 검출 문턱 |
| 1,000 | +9.32 | 90.0% |
| 300 | +11.71 | 98.7% |
| 100 | +11.90 | 99.7% |
| **40 (사양 상한 = 가장 약함)** | +10.89 | **100.0%** |
| 25 (사양) | +8.91 | 97.3% |
| 10 (사양 하한 = 가장 심함) | +2.20 | 48.0% ※ |

※ 비단조 — §5 한계 참조.

### 3.3 조건 C — 이중 영상 스윕 (사양 offset 18~28px)

| ghost offset (512 공간) | 평균 logit | FAIL 판정률 |
|---|---|---|
| **2px** | +3.84 | **49.7%** ← 검출 문턱 |
| 5px | +5.13 | 70.3% |
| 10px | +9.41 | 95.7% |
| **18px (사양 하한)** | +11.62 | **100.0%** |
| 28px | +13.16 | 100.0% |

### 3.4 해석

**깨끗한 용량-반응 곡선이 나왔다.** 강도를 낮추면 점수가 단조 감소하고 PASS로 돌아온다.
모델은 물리적 결함에 반응하고 있다.

검출 문턱이 사양보다 훨씬 낮다.

| | 검출 문턱 (50% 지점) | v1.9 사양 범위 | 배율 |
|---|---|---|---|
| 저신호 노이즈 | photon ≈ 3,000 | 10 ~ 40 | **약 100배 아래** |
| 이중 영상 | offset ≈ 2px | 18 ~ 28px | **약 9배 아래** |

**이것이 §2의 평평한 곡선을 설명한다.** 사양 구간 전체가 검출 문턱보다 수십~수백 배
심한 영역이므로, 그 안에서 강도를 바꿔도 이미 포화된 점수는 움직이지 않는다.

## 5. 한계 (반드시 함께 읽을 것)

1. **원본 raw 부재** — `E:\103.배터리 불량 이미지 데이터`가 없어 v1.9의 정확한 처리 순서
   (풀해상도 ROI에서 증강 → 512 축소 → JPEG)를 재현하지 못했다.
   프로브는 이미 512로 축소된 산출물에 증강을 걸었으므로 JPEG 세대가 하나 더 쌓인다.
   → 조건 A(재인코딩만, +0.02)로 이 confound가 무시할 수준임을 확인했다.

2. **증강 구현 단순화** — 저신호 노이즈를 4단계 중 1단계(Poisson)만 구현했고
   `signal_to_transmission`·`read_noise`·`low_contrast_attenuation`은 생략했다.
   그 영향이 photon=10에서 나타난다 — logit 2.20으로 photon=25(8.91)보다 **낮다**(비단조).
   극단 강도에서 근사가 학습 분포를 벗어난 것으로 보인다.
   → **검출 문턱의 절대값은 근사치**다. 정확한 값이 필요하면 원본 raw와 생성 코드가 있어야 한다.

3. **2개 케이스만 스윕** — `insufficient_projection_sampling`, `beam_hardening`,
   `cell_alignment`는 구현 비용 때문에 제외했다. 문턱이 케이스마다 다를 수 있다.

4. **단일 fold** — fold0 모델 하나로만 측정했다. 5-fold 반복 미실시.

5. **PASS의 대표성** — 우리 PASS는 "증강을 적용하지 않은 기준 이미지"일 뿐
   실제 촬영 변동폭을 대표하지 않는다. §6.1의 근거가 된다.

## 6. 새로 드러난 리스크와 다음 조치

### 6.1 🔴 민감도 과다 — 최우선 리스크

ghost **2px에서 이미 50%가 FAIL**이다. 실제 CT 촬영에서 이 수준의 미세한 흔들림은
드물지 않을 수 있다. 그렇다면 **실데이터에서 clean FPR이 3%를 크게 넘길 수 있다.**

현재의 clean FPR 3%는 "증강하지 않은 이미지" 기준이며 **실환경 값이 아니다.**
수율 손실 추정에 그대로 쓰면 안 된다.

### 6.2 조치 우선순위 (개정)

| 순위 | 조치 | 얻는 것 | 비고 |
|---|---|---|---|
| **1** | **shadow 모드 배포** | **실환경 clean FPR의 진짜 값** | 정상 사진은 현장에 충분하므로 **합성 데이터 없이 FPR 축을 측정할 수 있다.** 필터링을 하지 않으므로 수율 피해 0 |
| **2** | 실촬영 FAIL 확보 요청 | recall 축의 실환경 값 | 케이스당 20~30장, 평가 전용. 리드타임이 길어 지금 요청 |
| 3 | 나머지 3개 케이스 강도 스윕 | 케이스별 검출 문턱 완성 | 운영 사양 문장 완성 |
| 4 | leave-one-case-out | 미지 유형 대응력 + 규칙 vs MobileNet 실질 근거 | |
| 5 | PASS 오염 스캔 | clean FPR 숫자의 신뢰도 | |
| 6 | 5-fold 교차검증 | 오차 막대 | 우선순위 하향 (포화 영역 측정값) |
| — | lockbox 개봉 | 최종 확인 | **모든 개발 종료 후 1회만** |

**1순위가 shadow 모드로 바뀐 이유**: 이번 조사로 recall 축은 "사양보다 100배 약한 것까지
잡는다"는 답을 얻었다. 남은 미지수는 **FPR 축**이고, 그것은 실촬영 FAIL 없이도
현장의 정상 사진만으로 잴 수 있다. 가장 싸고 빠르게 가장 큰 불확실성을 줄이는 경로다.

또한 shadow 모드에서 점수 상위 N장을 사람이 확인하면 그 결과가 곧 2순위의 실촬영 FAIL
라벨이 된다. **"실데이터가 없어 검증 못 함 → 검증 못 해 배포 못 함"의 순환을 끊는다.**

### 6.3 운영점 권고 (잠정)

실환경 FPR이 확인되기 전까지 **clean FPR 상한을 1% 이하로 보수적으로** 잡는다.
recall이 다소 떨어져도 게이트가 없는 것보다 낫고 수율 피해가 없다.
`metrics_val.json`의 `thr@fpr1%`를 쓰면 되며 **재학습은 불필요하다.**
